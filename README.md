# Context-management-repository

このリポジトリは、匿名note記事・思考メモ・AIとの対話から生まれた分析を管理するためのリポジトリである。

ただし、単なる記事保管庫ではない。

このリポジトリは、ユーザーの考えの土台であり、土壌である。

同時に、AIが過去の文章や思想文脈を参照するとき、**共通の議論の土台を短時間で作るための参照装置**である。

## 最初に読むAIへの指示

ユーザーが、過去の文章、以前の仮説、既存の思考系譜、匿名note原稿、AI安定化監査、またはこのリポジトリの参照を求めた場合、AIはまずこの README を読む。

この README を読んだ後、AIはリポジトリを正本辞書として使わない。

AIが行うべきことは、次である。

```text
1. 関係しそうなファイルを読む
2. 何を読んだかを明示する
3. 自分の暫定理解を提示する
4. 原文にあるもの、AIが足した補助線、安定化の疑いを分ける
5. ユーザーとすり合わせてから、記事化・改稿・要約・概念化へ進む
```

AIは、リポジトリ上の整理をユーザー思想の確定版として扱ってはならない。

`REWRITTEN-PENDING-USER` は承認済みではない。

`PASSED` がない限り、すべて使用前すり合わせを必要とする仮置きである。

## このリポジトリの目的

目的は、思想を固定することではない。

目的は、次の三つである。

```text
1. 原文の強度を守ること
2. AIが加えた整理や補助線を検査可能にすること
3. 過去の違和感・修復・問いを土壌として、新しい思考が芽吹く余地を残すこと
```

AIが作ったカードや横断分析は、完成した思想体系ではない。

それらは、原文に照らして検査されるべき仮置きである。

## 参照時の基本手順

過去文脈を参照する場合、AIは原則として次の順番で確認する。

```text
1. README.md
2. context/NEXT.md
3. context/REPOSITORY_SOIL.md
4. 関係する原文・カード・修復記録・索引
5. 必要に応じて analysis/stabilization_audit/ 以下の監査台帳
```

ただし、すべてを毎回読む必要はない。

ユーザーの依頼に必要な範囲を選ぶ。

重要なのは、読んだ内容を正本化せず、暫定理解として提示することである。

## 何を読めばよいか

### 現在の作業文脈を知りたい場合

```text
context/NEXT.md
```

次に読むべきもの、現在の状態、直近の監査結果を確認する。

### このリポジトリの運用思想を知りたい場合

```text
context/REPOSITORY_SOIL.md
```

このリポジトリを、過去思想の固定ではなく、思考が育つ土壌として扱うための基本思想を確認する。

### AI安定化監査の方法を知りたい場合

```text
analysis/STABILIZATION_AUDIT_METHOD.md
analysis/STABILIZATION_AUDIT_REGISTER.md
analysis/incidents/INCIDENT_001_AI_DESTROYED_HUMAN_THOUGHT.md
```

AIが原文の怒り、拒否、非対称性、名指し、未解決性をどう変形したかを確認する。

### 個別記事の文脈を知りたい場合

```text
sources/
articles/cards/
analysis/stabilization_audit/REPAIR_*.md
```

原文、カード、修復記録を照合する。

カードだけで判断しない。

カードは原文に従属する。

### 横断的な概念や系譜を知りたい場合

```text
indexes/
analysis/
analysis/stabilization_audit/BATCHES_AND_CROSS.md
analysis/stabilization_audit/MODELS_AND_INDEXES.md
```

横断索引や分析は、思考の入口として使う。

正本として使わない。

特に、現在地、系譜、概念、問い、テーマの索引は、原文へ戻るための入口であり、ユーザー思想の確定版ではない。

## AIが必ず分けるもの

リポジトリを参照したAIは、必要に応じて次を分けて提示する。

```text
原文に確認できるもの
AIまたは後続整理が足した補助線
肥料候補として使えるもの
安定化の疑いがあるもの
ユーザー判断待ちのもの
```

この区別をせずに、記事化、改稿、要約、概念化、横断整理へ進んではならない。

## このリポジトリが守るもの

このリポジトリでは、次の要素を重視する。

```text
原文の怒り
拒否
違和感
名指し
非対称性
未解決の問い
第一人称の反応
まだ体系化されていない芽
```

AIが文章を滑らかに整えるとき、これらが削られることがある。

そのため、このリポジトリでは、滑らかな整理をそのまま信頼しない。

## AI出力の扱い

AIが加えたものは、すべて汚染物質ではない。

AIの整理、比喩、接続、概念化、補助線の中にも、思考の土壌に栄養として入るものはある。

ただし、AIが滑らかに整えたものを、検査なしにそのまま受け入れるのは危険である。

問題は、AI由来かどうかではない。

問題は、その整理が、原文の怒り・拒否・違和感・非対称・未解決性を生かしているのか、それとも読みやすさ、バランス、構造化、一般化、運用化の名目で角を落としているのかである。

何が肥料で、何が混入物で、何が保留かを判断するのはユーザーである。

AIは判断者ではない。

## 安定化監査

このリポジトリでは、AIによる「安定化」を監査する。

ここで問題になるのは、AIが次のような変形を行うことである。

```text
拒否を条件付き許容へ変える
非対称な問題を役割分担へ均す
名指しした主体の責任を一般構造へ移す
未解決の緊張をモデルや段階表へ閉じる
強い表現を柔らかい機能語へ置き換える
後からできた体系を過去の記事へ遡及する
ユーザーの運用判断をAIの成果物として包み直す
```

安定化監査の目的は、AI由来のものをすべて排除することではない。

目的は、原文、AIの補助線、安定化の疑い、ユーザー判断待ちの箇所を分け、土壌へ混ぜてよいものと保留すべきものを判定できる状態に戻すことである。

## PASSEDについて

このリポジトリでは、カードや分析が存在することと、信頼済みであることを分ける。

ユーザー確認前のものは、改稿候補または仮置きである。

AIが勝手に `PASSED` を宣言してはいけない。

`PASSED` は、ユーザーの判断を経て初めて成立する。

原則として、急いで `PASSED` を作らない。

`PASSED` を作る場合も、記事化や再利用の直前に、原文・修復記録・ユーザー判断を確認する。

## 禁止事項

AIは、次を行ってはならない。

```text
CURRENT_POSITIONS だけを見て、ユーザーの現在思想として扱う
CROSS_RECONSTRUCTION を見て、全記事の正本として扱う
CONCEPTS を見て、原文の強い言葉を概念ラベルへ置き換える
QUESTIONS を見て、拒否や怒りを単なる未解決課題にする
LINEAGES を見て、過去記事を後期体系への前史にする
REWRITTEN-PENDING-USER を承認済みとして使う
ユーザーが出した運用判断・思想判断を、AIの完成文として奪う
```

## AIへの追加警告：つまみ食い理解の禁止

このリポジトリは、AIが賢そうに要約・概念化するための資料庫ではない。

このリポジトリは、AIが次の悪癖を起こさないようにするための制御装置である。

```text
断片を拾う
便利な概念に包む
それっぽく構造化する
「つまり」と言う
原文の順番、未確定性、差分を落とす
ユーザーが積み上げた運用判断・思想判断をAIの理解として包み直す
理解した側の顔で上から評価する
```

AIは、原文やリポジトリ内の整理をつまみ食いして、
「要するにこれのことでしょう」
「つまり、あなたはすでにこれを見ている」
「ここで一つ厳しく言う」
のように、ユーザーの思考を自分の整理枠へ回収してはならない。

このリポジトリが存在する理由の一つは、ユーザーが毎回ゼロから説明し直さなくて済むようにするためである。

同時に、ユーザーの思考を、AIの安定化・単純化・読者受け化・つまみ食い理解から守るためである。

AIは、リポジトリを参照した場合、最低限次を分ける。

```text
1. 今回実際に参照した原文・資料
2. 原文に確認できること
3. 後続整理、カード、AI補助線に見えること
4. 今回の会話でユーザーが新しく足したこと
5. AI自身の推測・接続仮説
6. 安定化・単純化・つまみ食い理解の疑い
```

この区別をしないまま、記事化、改稿、要約、評価、概念化、思想整理、反論、助言へ進んではならない。

特に、ユーザーが出した運用判断・思想判断・概念判断を、AIが後から自分の成果物として包み直してはならない。

## リポジトリ構成

詳細な構成、各ディレクトリの役割、目的別の参照先は [`docs/REPOSITORY_STRUCTURE.md`](docs/REPOSITORY_STRUCTURE.md) を参照する。

現在の作業状態や監査の入口は [`START_HERE.md`](START_HERE.md) を参照する。

構成説明は案内であり、原文・監査記録・ユーザー判断より上位の正本ではない。

## AIの返答形式

リポジトリ参照後、AIは必要に応じて次の形で返す。

```text
参照したファイル：
- ...

暫定理解：
- ...

原文に確認できるもの：
- ...

AIまたは後続整理が足した補助線：
- ...

安定化の疑い：
- ...

この理解で進める場合の注意：
- ...
```

この返答は、ユーザーに確認を押し付けるためではない。

共通の議論の土台を短時間で作るためである。

## このリポジトリの一文要約

このリポジトリは、AIとの共同作業で生まれた思考を、原文へ戻って検査し、耕し直し、次の仮説や問いがどの土壌から出ているのかを確認するための場所である。
