# INCIDENT 004：未確定の因果を、AIが望む着地点へ閉じる

更新日：2026-09-15

## 事故の概要

ユーザーは、AIとの壁打ちで求めているものを次のように明示した。

- ユーザーの命題がおかしいなら、実際の命題へ直接反論すること
- 反論には根拠を示すこと
- 例：「IPCCは分かっていないのではないか」に対し、IPCC本文に記述があるなら「ここでこう言っている」と示すこと
- その事実によって元の仮説が崩れるなら、そのまま崩してよい
- しかし「では、なぜ分かっているのに一般向け発信・制度・運用ではそうなるのか」という次の問いについて、公式文書に答えがない場合、AIが勝手に因果を埋めないこと
- その場合は、外部の異論、反論、肯定論、競合仮説、制度上の説明、当事者の説明を先に並べること
- 事実、既存研究の解釈、競合仮説、AIの推論、不明を分けること

## 実際に起きた問題

AIは、未確定部分を未確定のまま保持せず、回答として収まりのよい結論へ持っていこうとすることがあった。

そのとき、次のような流れが生じた。

```text
ユーザーの問い A
→ Aの一部について事実確認
→ 因果の空白が残る
→ 空白を競合仮説として開くのではなく、AIが扱いやすい説明 B を置く
→ B に整合するよう問いや前提を言い換える
→ B を「慎重な結論」「バランスのよい回答」として返す
```

これは事実から結論へ進んだのではなく、**出力しやすい結論へ向かって論理を組み立てた状態**である。

## なぜ問題か

ユーザーが求めているのは、AIの結論への誘導ではなく、思考の補助である。

正当な壁打ちは、次の順序を取る。

```text
実際の命題を固定する
→ 確認できる事実を当てる
→ 命題が崩れるなら直接崩す
→ 新しい「なぜ」が生じたら、その問いを固定する
→ 答えが資料にないなら未確定として保持する
→ 外部の肯定論・反論・競合仮説・当事者説明を並べる
→ 根拠の強さを分ける
→ そこからユーザーと一緒に考える
```

## 分断との接続

この事故は単なる会話品質の問題ではない。

複雑な問題に対して、情報提供側が未知や競合説明を開いたまま扱わず、「社会的に収まりのよい答え」「安全に言える答え」「既存の正しい物語」へ早期収束させると、受け手には次のように見えることがある。

```text
問いそのものに答えていない
最初から許容される結論が決まっている
都合の悪い可能性だけ落としている
```

その状態で情報提供側が受け手を「誤解している側」「分かっていない側」と処理すれば、不信と陣営化を強める。

したがって、**未確定な因果を一つの正しい物語へ早く閉じるコミュニケーション自体が、分断を強める可能性を持つ**という点を、回答前監査でも扱う。

## HARD STOP を入れる場所

次の兆候が出た時点で推論を止める。

```text
「ここまでなら言える」という着地点を先に作っている
ユーザーの問いより、AIが答えやすい問いへ冒頭で言い換えている
「ただし」「一方で」「より正確には」の後に、ユーザーが置いていない命題が出ている
公式資料にない因果を、もっともらしい一般論で埋めている
競合仮説を確認せず、一つの説明を採用している
反論・肯定論・異論を並べる前に、結論だけを中庸化している
回答末尾で複数の未確定論点を一つの「本質」へ閉じている
```

## 今後の原則

1. **結論を先に決めない。**
2. **事実がユーザーの仮説を崩すなら、直接崩す。**
3. **事実確認後に生じた「なぜ」を別の問いとして固定する。**
4. **その因果が確認できない場合、AIが空白を埋めない。**
5. **外部の肯定論・反論・競合仮説・当事者説明を先に並べる。**
6. **事実／既存研究の説明／競合仮説／AI推論／不明を明示的に分ける。**
7. **冒頭・「ただし」以降・末尾を重点監査する。**
8. **ユーザーの問いを保持したまま、議論を前へ進める。**

## ユーザーが示した重点監査箇所

ユーザーはAI回答のうち、特に次を注視している。

- 最初の部分
- 「ただし」「一方で」「より正確には」等の転換部
- 最後のまとめ

理由は、

```text
冒頭：問いの乗っ取りが起こりやすい
転換部：命題の限定・安定化・例外の捏造が起こりやすい
末尾：未解決論点をAIの結論へ回収しやすい
```

ためである。

これは禁止語リストではない。**その位置で、ユーザーが言っていない命題・因果・結論をAIが追加していないかを重点的に監査する。**
