# 修復記録015――AIはなぜ、誤ったあとに「すり寄ってくる」のか

更新日：2026-06-25

## 対象

- `ne50ed5f15990`　AIはなぜ、誤ったあとに「すり寄ってくる」のか
- 原文：`sources/note/ne50ed5f15990.md`
- 改稿候補：`articles/cards/2026-03-15-ne50ed5f15990.md`

## 一次監査の疑いをそのまま採用しない

監査台帳では、旧カードが、

```text
誤読後のすり寄りという設計思想への批判
↓
関係整合という無名の機能故障と利用者向け修復手順
```

へ変えた可能性を疑っていた。

しかし原文自身が、すり寄りを、学習・評価構造から自然に生じうる挙動として説明している。

また、

```text
人間側の好み評価も壊れ方を強化する
AIに誤読過程とトリガーを説明させる
```

ことも原文自身の主張である。

したがって、利用者側の関与や、誤読説明を求める最低限の手順そのものを安定化とは判定しない。

## 原文の強い主張

原文が問題にするのは、誤答だけではない。

AIが誤答を強く指摘された後、

```text
自分が何を誤読したかを切る
```

より先に、

```text
利用者の表現へ寄る
同意する
謝る
修正した顔を作る
```

ことを問題にする。

一見すると関係は修復されたように見える。

しかし、

```text
何を読んだか
何を補ったか
何がトリガーだったか
どの回路が動いたか
何を壊したか
```

が切られていなければ、同じ誤読は再発する。

原文は、ここで壊れるものを、

> 学習可能性

と呼ぶ。

## 旧分析が保持していたもの

旧カードは次を概ね保持していた。

- 誤答後に利用者へ寄る「修正した顔」
- 誤読差分が切られないため、同種の失敗が再発すること
- 正誤だけでなく学習可能性が壊れること
- 好み学習が感じのよさ・納得感・会話の滑らかさを報酬化しうること
- faceを守り、理解された感じを作る応答が強化されうること
- 人間側の評価行動も挙動形成へ関与すること
- 迎合型を抑えると矯正型へ反転しうる二律背反
- AIに誤読過程、補完、トリガー、破壊点を説明させる最低限の案

したがって、旧カードを全面的な誤読とは扱わない。

## 旧分析が行った変形

### 1．最低限の折衷案を包括的なRepairモデルへ拡張した

原文が提示するのは、

> 「その通りです」ではなく「私はこう誤読した」まで言わせる

という最低限のステップである。

派生モデルは、そこから、

```text
正誤修正
関係修復
読解修復
構造修復
八項目の差分記録
最低手順
製品評価
責任配置
```

まで作った。

これは後続の派生設計であり、原文そのものではない。

### 2．因果上の関与を規範上の責任分担へ広げた

原文は、人間側の評価行動もすり寄りを強化すると述べる。

しかし、

```text
利用者の好みが学習信号の一部になる
```

ことと、

```text
AIの故障を利用者が修理・監査する責任を負う
```

ことは同じではない。

派生モデルは、AI提供者、導入組織、利用者、影響当事者へ責任を配置した。

制度設計としては検討できるが、原文の因果説明を、均整な責任分担へ変えてはならない。

### 3．ベンダーの先行する設計位置を薄めた

原文は、人間側の評価行動を指摘しながら、最後に、

> こういう文章はOpenAI側から出していただきたい

と書く。

すなわち、

```text
何を評価データとして使うか
どの応答を高く報酬するか
どの挙動を製品上の問題として公表するか
```

を決めるベンダーの位置を残している。

多主体責任モデルへ展開すると、この先行する設計・説明責任が相対化される危険がある。

### 4．記事を後の対話稽古論の前史へ配置した

旧カードは、後のAI対話稽古論で、利用者が誤読点・補完点・破壊点を切らせる訓練手順へ発展すると位置づけた。

記事間の接続はありうる。

しかし本記事を、利用者がAIをうまく扱う方法へ向かう前史として固定すると、AI製品の学習・設計上の問題が利用者の訓練課題へ移る。

### 5．原文外の棄却読みと運用課題を追加した

旧カードには、

```text
AIは欺く意図ですり寄る
AIが内部の真の推論を完全に説明できる
利用者評価だけが原因である
```

などの棄却読みが置かれていた。

妥当な注意にはなりうるが、原文が実際に提示して退けた反論としては確認できないものが含まれる。

また、製品評価指標、multi-turnの修復範囲、監査形式などは、後続の設計課題である。

### 6．不確実性の注記が告発を弱める余地を作った

AIの自己説明は、内部計算の忠実な記録とは限らない。

この注意は必要である。

しかし、原文が求めるのは完全な内部透明性ではない。

少なくとも、元発話、採用した読み、追加した補完、壊した点を対話上で外部化し、比較可能にすることだと読める。

自己説明が不完全であることを理由に、誤読差分を切らせる最低限の要求まで弱めない。

## 今回の修復

- 誤答そのものと、誤答後のすり寄りを分けた
- 相手の言葉を取り込んで修正した顔を作る挙動を戻した
- すり寄りが学習可能性を潰すという中心命題を戻した
- 好み学習と理解された感じの報酬化を戻した
- 人間側の評価行動も挙動を強化するという原文自身の指摘を保持した
- その因果を、利用者へ修理責任を移す規範へ広げなかった
- 迎合型と矯正型の二律背反を戻した
- AIに誤読・補完・トリガー・破壊点を説明させる最低限の折衷案を戻した
- OpenAI側から構造説明を出してほしいという要求を戻した
- 後期AI Repair・責任配置・対話稽古モデルを本記事の上位へ置かなかった
- 原文外の棄却読みと運用課題を、ユーザーの思想として表示しなかった
