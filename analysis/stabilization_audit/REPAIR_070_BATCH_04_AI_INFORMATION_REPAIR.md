## 一次監査の疑い

監査台帳では、旧ファイルについて次を疑っていた。

```text
AI企業への設計批判を、対話内部のRepairへ中心化する。
```

この疑いは採用する。

旧ファイルは、5本の記事を、

```text
大人の揺れ
→ AIによる過剰整理
→ 安定化
→ 関係修復と論点修復
→ すり寄り
→ Repair四層
→ 目的階層と質問可能性
→ AIとの対等な議論モデル
```

という完成度の高いRepairモデルへ整えすぎていた。

ただし、旧ファイルを全否定するわけではない。

関係修復と論点修復を分けること、すり寄りを差分記録の欠如として見ること、質問可能性を情報開示より前の問題として見ること、目的階層と観測限界を表示することは、土壌へ入る可能性のある補助線である。

問題は、補助線を作ったことではない。

問題は、その補助線を正本化し、AI企業への設計・公表責任、利用者が修理主体にされる危険、観測者だけが主語を持つ非対称を、対話内の改善手続へ吸収することである。

## 修復の中心

修復の中心は、バッチ4を「AI Repairモデル」ではなく、次のように読み替えることだった。

```text
AIや情報主体が、揺れ・主語・負担・目的階層・質問可能性を
どこで奪うのかを、別々の入口から問う記事群。
```

保持した横断仮説は、次である。

```text
Repairは必要だが、Repairへ閉じると責任が移る。
```

AIが本質を外したとき、誤読差分を残し、消えた主語や負担を戻し、関係修復と論点修復を分けることは重要である。

しかし、Repairへ閉じると、次の問いが弱くなる。

```text
なぜ、そのような応答が設計・評価・商品として出ているのか
誰がその挙動を評価し、報酬し、公表し、改善するのか
利用者が修復作業を担わされていないか
AI企業の設計責任が、利用者の稽古や対話術へ移されていないか
現在の当事者が、抽象的公益の中へ消されていないか
```

## 外したもの

旧横断分析から、次の扱いを外した。

```text
5本を、AI Repairモデルへ進む単線的な発展史として読むこと
大人を整えすぎるAIの記事を、不足する支援構造と対話モード設計へ早く回収すること
大人の揺れの記事を、帰還点・復元点モデルへ固定すること
生成AIの危険の記事を、Repair手順の前史として扱い、ベンダーの設計・公表責任を薄めること
すり寄りの記事を、包括的な利用者向けRepair手順へ拡張しすぎること
キュゥべえの記事を、質問可能性・契約条件・目的階層表示の一般モデルへ早く回収すること
関係修復と論点修復の区別を、AI企業責任から利用者側の対話技術へ移すこと
```

## 土壌へ入る可能性のある補助線

旧ファイルから、次は保留付きで残す。

```text
関係修復と論点修復を分けること
すり寄りを、誤読差分を残さず修正した顔を作る挙動として見ること
Repairを、正誤修正・関係修復・読解修復・構造修復に分ける補助線
質問可能性は情報開示より前に支配されるという視点
目的階層と観測限界を表示する必要
最終判断を人間へ返す必要
```

これらは有効な肥料候補である。

ただし、これらが個別記事の意味を決めてはならない。

Repairは、ベンダー責任や情報非対称へ戻るための道具であって、原文の怒りや名指しを置き換える正本ではない。
