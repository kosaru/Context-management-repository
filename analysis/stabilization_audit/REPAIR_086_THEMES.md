# 修復記録086――テーマ索引

更新日：2026-06-29

## 対象

- 改稿候補：`indexes/THEMES.md`
- 監査台帳：`analysis/stabilization_audit/BATCHES_AND_CROSS.md`
- 運用思想：`context/REPOSITORY_SOIL.md`

## 一次監査の疑い

```text
テーマ分類が記事の固有性を削る可能性。
```

この疑いは採用する。

旧ファイルは、記事を分類箱へ閉じ込めるのではなく、どの問題領域から全体へ入り、どの系譜へ接続できるかを示す、と明記していた。

しかし実際には、12のテーマを立て、問題領域、主な系譜、代表的な後期記事、注意を並べていた。

この整理には有効な補助線がある。

ただし、そのまま正本化すると、各記事はテーマの代表例や接続先になり、記事固有の怒り、拒否、発生地点、迷い、複数テーマへのまたがり、テーマからはみ出す部分が見えにくくなる。

## 修復の中心

テーマ索引を、記事の分類表として扱わない。

次のように仮置きした。

```text
テーマ索引は、記事を分類箱へ入れる正本ではない。

テーマは、原文へ戻るための検索入口である。

生活、減速、責任配置、Security / Comfort、倫理、読解、身体・科学、AI、情報非対称性、国際秩序、制度目的化、物語作品は、たしかに複数記事をまたいで反復する。

しかし、それらは記事の所属先ではない。

テーマ索引の役割は、
どの入口から記事へ戻れるか、
そのテーマで見えやすくなるものは何か、
そのテーマで消えやすくなるものは何か、
複数テーマにまたがることでまだ固定できないものは何かを分けることである。

接続できる。
しかし、テーマへ所属させてよいとは限らない。
```

```text

テーマを、分類箱ではなく問題領域から全体へ入る入口として扱うこと
成立順、系譜、現在地、記事役割への参照先を分けること
生活保障、減速、保存・再設計・回転、Security / Comfort、倫理、読解、身体・科学、AI、情報非対称性、国際秩序、制度目的化、物語作品を入口として置くこと
各テーマに注意を置き、単純化を防ぐこと
テーマが複数の系譜へ接続すること
代表記事を検索入口として使うこと
```
