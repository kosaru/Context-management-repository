## 収集・更新方針

現在解析済みの25記事は、note全記事ではない。

初回取得で収集できた25記事を対象に、記事カード、系譜、横断索引を作成した。今後の全体分析は、スクレイピング結果だけに依存せず、noteエクスポートを初期コーパスと記事目録の基準にする。

全体分析完了後は、定期スクレイピングを新着記事・本文更新・公開状態変更の差分検出に使う。

```text
noteエクスポート
  = 初期コーパスと記事目録の基準

note公開ページ
  = 公開中の最新本文の正本

定期スクレイピング
  = 新着・更新・公開状態の差分検出

GitHub
  = 記事カード、系譜、現在の立場、概念、問いの正本
```

エクスポート原本には下書きや限定公開情報が含まれる可能性があるため、内容確認前に原本をそのままGit履歴へ入れない。公開対象として正規化した目録と本文スナップショットをリポジトリへ追加する。

詳細は `docs/INGESTION_WORKFLOW.md` を参照する。

## この文章群が目指すもの

匿名noteの記事を、単発の意見ではなく、問いが別の記事へ移動しながら育つ思考過程として扱う。

文章の評価では、読みやすさや構成の整い方より先に、読者の中へ問いや考える余地を残す「思考の種」になっているかを見る。

批判を書く場合は、告発だけで閉じず、何がその状態を作っているのかという構造と、どこを再設計できるのかまで見る。

## 最上位の問い

> 人類は、どうすれば滅びずに続くのか。

環境、AI、政治、経済、都市、少子化、社会制度は、この問いの下位に置く。

ただし、この最上位命題が記事群全体のどこまで一貫して維持されているかは、エクスポートから取得する全記事を含めて再確認する。

## 現在維持している編集原則

- 内容を薄めず、読者が迷子にならないように重心と通りを整える。
- 具体的な出来事から論へ接続し、抽象論だけの空中戦にしない。
- 非対称な問題を、無理に対称な整理へ戻さない。
- 二項対立そのものを消すのではなく、それが理屈や動員材料として使われ、固定化される構造を見る。
- 批判対象と同じ場所に立たずに済む代案や再設計可能性を探す。
- 不明な事実をもっともらしく補わない。

## 議論を進めるための機能

### 保存

共有済みの前提、問いの芯、暫定固定、文脈の重心を保持する。

### 再設計

既存の文脈を壊さず、その論理を内側から押し広げる。

### 回転

保存と再設計を往復できる状態を保つ。真ん中を取ること、両論併記、内容を薄めることとは区別する。

## 取得済み25記事から見える共通運動

1. 既存の概念、制度、技術が持つ必要な機能を保存する。
2. その機能が別の目的へ反転する地点を探す。
3. 混同されている主語、階層、工程、責任を分ける。
4. 個人の善意、努力、我慢へ押しつけられた機能を、社会的条件へ戻す。
5. 理念を、欲望、指標、価格、処理先、制度、契約、内部条件へ降ろす。
6. 検証可能性、選択可能性、可逆性を回復する。
7. 制度側で分解された責任を、生活側の現実から再統合する。
8. 結論によって消された摩擦、負担、未確認範囲を保存し、戻る場所を残す。
9. 単一の保証や説明へ集約せず、複数の出口と担保を持つことで交渉可能性を増やす。

これらは完成した思想体系ではない。未取得記事によって、前史、別系譜、反例、修正が加わる可能性を残す。

### 継続運用

全体分析完了後、定期スクレイピングで次の差分だけを追加する。

- 新着記事
- 既存記事の本文更新
- タイトル変更
- 公開・非公開状態の変更

自動取得結果で解析済みカードを上書きしない。本文差分が論旨へ影響する場合だけ、人間が確認したうえでカードと系譜を更新する。
