# note記事の取り込み・更新運用

更新日：2026-06-24

## 方針

記事群全体の初期構築には、noteのエクスポートデータを使う。

初期構築と全体解析が完了した後は、スクレイピングを新着記事・公開本文の変更・公開状態の差分検出に使う。

```text
noteエクスポート
  = 初期コーパスと記事目録の基準

note公開ページ
  = 公開中の最新版本文の正本

定期スクレイピング
  = 新着・更新・公開状態の差分検出

GitHub
  = 記事カード、系譜、現在の立場、概念、問いの正本
```

## エクスポート原本の扱い

エクスポート原本には、公開記事以外の情報、下書き、限定公開情報、内部メタデータが含まれる可能性がある。

そのため、内容を確認する前に原本をそのままGit履歴へコミットしない。

原則として次の順序で扱う。

1. エクスポートファイルを作業用入力として受け取る。
2. ファイル形式と収録対象を確認する。
3. 記事単位へ分解する。
4. 公開・下書き・限定公開などの状態を分ける。
5. 公開対象として扱う記事だけを正規化する。
6. 正規化した目録と本文スナップショットをGitHubへ入れる。
7. 原本を保存する場合は、公開可否と保存場所を別途決める。

## フェーズA：全体コーパスの確定

### 1．記事目録を作る

エクスポートから、可能な範囲で次を抽出する。

- note記事ID
- タイトル
- 公開日時
- 更新日時
- 公開状態
- 公開URL
- 本文
- タグまたはカテゴリ
- エクスポート内の識別子

記事IDが取得できない場合は、公開URL、タイトル、公開日を組み合わせて暫定的に照合する。

### 2．既存25記事と突き合わせる

```text
エクスポートにもGitHubにもある
  → 既存の解析カードを維持し、本文差分だけ確認する

エクスポートにはあるがGitHubにない
  → 新規記事として本文スナップショットと未解析カードを作る

GitHubにはあるがエクスポートにない
  → 削除、限定公開、エクスポート対象外、照合失敗を確認する

本文またはタイトルが異なる
  → 更新差分として記録し、解析カードへの影響を確認する
```

### 3．全記事を時系列で解析する

直近記事から過去を推定するだけでなく、古い記事から次を追う。

- 問いの初出
- 後の記事で維持された前提
- 修正された概念
- 棄却された見方
- 一時的に途切れた系譜
- 後から再発見・再命名された問題

### 4．横断索引を再構築する

全体解析後、次を初回取得25記事版から全記事版へ更新する。

- `context/CURRENT.md`
- `indexes/CURRENT_POSITIONS.md`
- `indexes/LINEAGES.md`
- `indexes/THEMES.md`
- `indexes/CONCEPTS.md`
- `indexes/QUESTIONS.md`
- `indexes/UNRESOLVED_QUESTIONS.md`

## フェーズB：定期スクレイピングによる追加運用

全体解析完了後、スクレイピングは全体の正本を作るためではなく、差分検出のために使う。

### 定期処理

1. note公開一覧から記事ID・URL・公開日を取得する。
2. 前回の目録と比較する。
3. 新しい記事だけを取得する。
4. 既存記事は、更新日時または本文ハッシュが変わった場合だけ再取得する。
5. 削除・非公開化の可能性がある記事を別に記録する。
6. 新規記事へ未解析カードを作る。
7. 解析後、関連する系譜・概念・問いだけを更新する。

### スクレイピングで上書きしないもの

- 解析済み記事カード
- 人間が確認した記事間関係
- 現在の立場
- 未解決問題
- 本文と解析の境界に関する注記

公開本文が変わった場合も、自動的に解析カードを上書きしない。差分を示し、文脈への影響を確認してから更新する。

## 差分管理

記事ごとに、少なくとも次を保持する。

```text
note_id
published_at
last_seen_at
source_updated_at
content_hash
public_status
snapshot_path
card_path
analysis_status
```

本文の変更を検出した場合は、次を分ける。

- 誤字修正や表現調整
- 論旨に影響する追記・削除
- タイトル変更
- 公開状態の変更

論旨に影響する変更だけを、記事カードと系譜の再確認対象にする。

## 定期実行の頻度

頻度は全体解析完了後に決める。

候補は週1回を基本とし、投稿頻度が高い期間だけ毎日または手動実行を併用する。

毎回すべての本文を再取得せず、一覧と更新情報を先に比較してから必要な記事だけ取得する。

## 完了条件

### 初期構築の完了

- エクスポート収録件数を確定した
- 公開対象の記事目録を作成した
- 既存25記事との照合を終えた
- 全対象記事の記事カードを作成した
- 全対象記事の解析を終えた
- 横断索引を全記事版へ更新した

### 継続運用の完了

各定期実行で、次が満たされれば完了とする。

- 新着・更新・公開状態の差分を検出した
- 新着記事のスナップショットとカードを追加した
- 更新記事の差分を記録した
- 必要な系譜・問い・現在地を更新した
- 自動取得失敗を全件取得完了と誤認していない
