# 文章作成プロセスと生成作業の責任分担

制定：2026-09-27（ユーザー指示）

## 適用範囲と出所

この文書は、2026-09-25の匿名note記事作成を振り返る対話で整理した文章作成プロセスを、今後の記事・原稿作成に用いるための運用手順である。工程の採用と以下の責任分担は、2026-09-27のユーザーの明示的な判断による。工程の文章化はAIの作業であり、ユーザーの思想上の新しい命題として帰属しない。

後半の「生成作業の責任分担」は、記事・原稿に限らず、ユーザーが依頼する生成作業全般に適用する。個々の依頼でユーザーが目的・対象・制約を指定した場合は、その指定を保持する。この手順を理由に目的や完成条件を追加・変更しない。

## 文章作成の順番と各段階の確認

各段階の出力を次の段階へ渡す前に、問い・主語・順序・帰属が保持されているか確認する。途中でずれを見つけた場合は、表現だけを整えず、ずれが生じた段階まで戻る。

| 順番 | 進める作業 | 次へ渡す前に確認すること |
| --- | --- | --- |
| 1. 文章化前に議論する | ユーザーが置いた問いから、必要な概念の区別、具体例、反例、未解決点を検討する。 | 出発点の問い・対象・射程を保っているか。比較や具体例が、指示されていない別の主題に昇格していないか。ユーザーがまだ記事化を指示していない段階では、その判断を先取りしない。 |
| 2. 記事の目的と射程を定める | ユーザーが文章化を求めた時点で、題名、中心の問い、記事全体で扱うことと個別の例として扱うことを整理する。 | 目的や評価基準をAIが作り替えていないか。題名と中心の問いが一致するか。未決定事項を決定済みとしていないか。 |
| 3. 過去の原文と資料を照合する | 必要な過去記事・原文・修復記録を読み、必要な外部資料を確認する。リポジトリ参照時はREADMEと関係する原文・監査記録をたどる。 | 過去に述べたことと今回初めて接続したことを分けたか。原文、資料上の事実、ユーザーの判断、AIの補助線、不明を混同していないか。過去の文章を今回の結論へ遡及させていないか。 |
| 4. 論点の順番を組む | 読者が前提から問いを追えるよう、必要な具体例と論理の接続を配置する。 | 主語、因果、責任や負担を引き受ける人が途中で入れ替わっていないか。必要な前提を飛ばしていないか。対立や非対称性を形式上の均衡で消していないか。 |
| 5. 草稿を作る | AIが、指示された範囲の本文と必要な補記を、読者が辿れる文章として作成する。 | 議論で確かめた内容が短縮・言い換え・均衡化によって変形していないか。必要な説明、語の強さ、未解決の問いが残っているか。 |
| 6. ずれた段階まで戻して改稿する | AIが草稿と元の問い・原文を照合し、ユーザーの差し戻しも取り込む。一文の問題か、構成か、問いや前提の取り違えかを特定する。 | 原因が構成や前提にあるのに局所的な加筆で済ませていないか。修正後に新たな変形を起こしていないか。必要なら段階1〜5へ戻る。 |
| 7. 本文と補記を仕上げる | 本文の流れを完成させ、依頼された補記には研究・資料との接点と差分、過去記事との関係を記す。 | 研究者や資料が述べたことと本文独自の展開を分けたか。過去記事との接続を事後的な体系にしていないか。未解決部分を無難な結論で閉じていないか。 |
| 8. サムネイル画像を作る | 完成稿の題名と本文を踏まえ、AIが記事用のサムネイル画像を作成して提示する。 | 画像が本文の中心の問いを表しているか。本文にない主張や、対象・主体・関係の取り違えを視覚表現で加えていないか。サムネイルとして見える形になっているか。 |
| 9. タグ案を考える | 完成稿に沿って、AIが公開時に使うタグ案を作成して提示する。 | タグの語と組み合わせが本文の内容を表し、記事の主題や射程を別のものへずらしていないか。 |

この表は、途中でユーザーの問いが更新されたときの戻りを妨げない。各段階で新たに必要になった確認はAIが実行し、結果と限界を示す。資料不足なら推測で完成させず、不足している資料や未確認の箇所を明示する。

## 生成作業全般の責任分担

| 責任の所在 | 担うこと |
| --- | --- |
| ユーザー | 文章のネタを出す。AIが作った成果物を受け入れるかどうかを検収し、採否と必要な修正を判断する。思想・運用上の判断と、ユーザー自身の発言の意味を決める。 |
| AI | 依頼された生成作業全般の進捗管理、必要な調査・原文確認、構成、草稿・サムネイル画像・タグ案を含む成果物の作成、改稿、自己監査、未完了事項の整理、成果物の提示と完了報告を担う。指摘されたずれを原因の段階まで戻って修正する。各作業では、このリポジトリに記載された該当する基準を確認し、それに従う。 |

AIは、進捗を把握し、現在の段階、作成済みの成果物、確認済み・未確認の事項、次に必要な作業を管理する。作業を進めるための下位手順や成果物の作成を、ユーザーに差し戻して管理させない。検収に出す前に、AI側で実行可能な作成・確認・修正を終える。

AIによる自己監査や「完成」の報告は、ユーザーによる受け入れ検収を意味しない。ユーザーが差し戻した場合、AIは何が否定されたかを特定して修正し、再提示する。ユーザーの判断をAIが代行したり、未検収の成果物を承認済みと記録したりしない。

## 進捗・成果物の記録

作業の途中と提示時に、AIは必要に応じて次を簡潔に記録・報告する。

- 現在の段階と完了済みの作業
- 作成した成果物と所在
- 根拠を確認した事項と未確認の事項
- 残る作業、差し戻し箇所、修正の状態
- ユーザー検収の状態（未提示／提示済み・検収待ち／差し戻し／受け入れ済み）

「受け入れ済み」はユーザーの判断が実際にあった場合に限る。既存のPENDING、REWRITTEN-PENDING-USER、PASSEDの扱いをこの文書で変更しない。個別記事のカード・原文・監査記録については、従来の状態と優先順位を維持する。
