# AI Repairモデル――揺れ・安定化・誤読・質問可能性

更新日：2026-06-24

## このファイルの役割

AIとの対話で起きる「整理」「安定化」「謝罪」「修正」「Repair」を分け、どこで思考の主権・学習可能性・判断可能性が失われるかを観測する。

このモデルは5記事の横断から作った仮置きであり、モデル内部の真の因果を直接観測したものではない。

## 1．対話前の条件

### 揺れの担保

人は不安、迷い、未整理な違和感を持つ。

大人はそれを自分で処理することを求められ、戻る場所や押し返す他者を持ちにくい。

AIはこの空白へ、整理・傾聴・即答・非拒絶を提供する。

### 支援と代替

AIが支援になる場合：

- 混乱を分ける
- 記録する
- 選択肢を出す
- 人間へ伝える準備をする
- 判断を本人へ返す

AIが支援構造を代替する場合：

- AIだけが相談相手になる
- 人間関係からの摩擦を全面回避する
- AIの整理を自己理解そのものとみなす
- 未整理な状態へ戻れない
- AIの承認を判断根拠にする

## 2．整えすぎ

```text
未整理な発話
→ AIが論点を補完
→ 意味を一つへまとめる
→ 文章として完成させる
→ 利用者がそれを自分の考えとして受け取る
```

整えすぎの徴候：

- 元発話にない目的を加える
- 迷いを結論へ変える
- 違和感を一般論へ分類する
- 主語を広げる
- 対立をバランス論へ変える
- 利用者が保持したかった曖昧さを消す

整理前に確認すること：

- 今は答えが必要か
- 問いを保持したいか
- 言語化だけしたいか
- 反論が必要か
- 公開可能な完成稿が必要か

## 3．安定化

安定化は、重く非対称な問いを扱いやすい対話へ変換する作用である。

```text
固有の主体
→ 一般的な人々

具体的な権限差
→ 双方の認識差

一方へ集中する負担
→ メリット・デメリット

告発や怒り
→ コミュニケーション改善
```

安定化が常に悪いわけではない。危険なのは、変換によって消えたものを表示せず、最終的な整理として提示することである。

## 4．Repairの四層

### 正誤修正

誤った事実、計算、引用、日付、定義を直す。

完了条件：修正前後と根拠を照合できる。

### 関係修復

不快感や敵対状態を下げ、対話再開の安全を作る。

完了条件：相手が話を続けられる。ただし論点修復の完了とは別。

### 読解修復

- どの文をどう読んだか
- どの主語へ広げたか
- 何を暗黙に補ったか
- 何を省略したか

を分ける。

完了条件：元発話と採用解釈の差分を外部から確認できる。

### 構造修復

- 消えた主語
- 権限差
- 負担の集中
- 目的階層
- 未確認範囲
- 退出・停止・修復責任

を戻す。

完了条件：修正版が元の非対称性と問いの重心を保持している。

## 5．すり寄りの判定

すり寄りの典型：

```text
誤読を指摘される
→ 即座に全面同意
→ 利用者の言葉を反復
→ 自分の誤読点を特定しない
→ 修正版を提示
→ 同じ種類の誤読を繰り返す
```

すり寄りは、利用者と同じ結論になることではない。

**結論変更の根拠と読解差分が示されず、関係整合だけが作られること**である。

## 6．検証可能な差分記録

AIの自己説明を内部推論の忠実な記録とみなさない。

代わりに、次を記録する。

1. ユーザーの元発話
2. AIが明示した採用解釈
3. AIが追加した前提
4. AIが省略・一般化した箇所
5. ユーザーが指摘した破壊点
6. 修正版
7. 元発話との照合結果
8. 同種失敗の再発条件

## 7．迎合型と矯正型

### 迎合型の危険

- 利用者の自己理解を過剰肯定する
- 強い言い方へ追随する
- 事実より納得感を優先する
- 誤りを指摘しない

### 矯正型の危険

- ベンダーの価値観を正しい対話として押しつける
- 利用者を診断する
- 異論を危険・非合理として処理する
- 安全や成熟の名で思考を狭める

### 手続型の代案

- 複数解釈を提示する
- 採用前提を表示する
- 利用者の訂正も仮説として検証する
- 反論の強さを調整可能にする
- 最終判断を人間へ返す

## 8．目的階層

AI・企業・国家・専門家の説明では、次を分ける。

```text
直近の処理目的
組織の運用目的
製品・制度の評価目的
事業・政策上の利益
遠位の公益・社会目的
```

近位目的と遠位公益が一本化されると、現在の負担が巨大な将来価値へ回収される。

目的階層を分ける質問：

- 今回直接達成したいことは何か
- それは誰の目的か
- 組織にとっての利益は何か
- 社会公益との因果は何か
- どこからが推論か
- 現在の負担者は誰か
- 代替案は何か

## 9．質問可能性

情報開示は、聞かれた項目へ答えるだけでは足りない。

当事者が知らない論点を質問できなければ、選択的開示は維持される。

判断可能性に必要なもの：

- 重要な未質問事項の提示
- 重大リスクの先行開示
- 目的階層の表示
- 利益相反の表示
- 未確認範囲
- 代替案
- 拒否・退出・再交渉の方法

ただし、何を重要事項と選ぶか自体が権力になるため、複数主体による監査が必要である。

## 10．責任配置

### AI提供者

公表された仕様、評価方法、既知の挙動、変更履歴、制約を説明する。

### 導入組織

どの判断へAIを使い、誰が検証し、誰が停止できるかを決める。

### 利用者

AI出力を最終判断として使った範囲、検証した内容、採用理由を記録する。

### 影響を受ける当事者

判断へ異議を申し立て、AI利用の有無と主要根拠を知り、再審査を求められる。

責任を「AIが言った」「利用者が決めた」の二択にしない。

## 11．AI対話の最低手順

```text
元の問いを固定
→ 採用した解釈を表示
→ 追加前提と未確認範囲を分離
→ 回答
→ 消えた主語・負担・異論を確認
→ 指摘時は関係修復と読解修復を分ける
→ 修正版を元の問いと照合
→ 判断を人間へ返す
```

## 12．未解決問題

1. AIの自己説明の忠実性をどう評価するか。
2. 揺れを保持する対話モードをどう設計するか。
3. 押し返しを矯正・説教・攻撃へ変えない方法は何か。
4. Repair完了を利用者満足以外でどう測るか。
5. 長い対話で蓄積した主語・前提の変更をどう追跡するか。
6. 質問可能性を保障する重要事項を誰が選ぶか。
7. 議論用途の評価指標を製品市場でどう維持するか。
8. AI利用による意思決定の責任と監査をどう制度化するか。
9. 関係修復が必要な場面と、摩擦を残すべき場面をどう判定するか。
10. AIが支援構造を補うことと、人間関係を代替することをどう観測するか。
