# 責任配置モデル――分界・決定・退出・修復

更新日：2026-06-24

## このファイルの役割

バッチ2の7記事から抽出した責任配置の現在地をまとめる。

責任者の名札を付けるためではない。

```text
誰が決め
誰が実装し
誰が説明し
誰が監査し
誰が負担し
誰が止め
誰が直し
誰が次へ渡すか
```

の連結が切れていないかを見るための観測モデルである。

各記事がこの八分類をそのまま提示したわけではない。記事群を横断して作った現在の仮置きであり、今後の具象で修正する。

## 1．責任を八つへ仮分解する

### 決定責任

どの前提、目的、代替案から一案を選び、時間を一度固定したか。

決定責任は、結果を完全に予知する責任ではない。決定時点の情報、未確認範囲、採否理由を引き受ける責任である。

### 実装責任

決定を現場の手順、資源、人員、契約、接触条件へ変換したか。

決定内容が正しくても、実装不能や現場への丸投げで壊れる。実装主体を決定主体の影へ隠さない。

### 説明責任

何を目的に選び、何を捨て、誰へどの負担が出るかを説明する。

説明は正当化作文ではない。後から判断経路を検証できる材料を供給する責任である。

### 監査責任

決定前提、実装状況、結果、記録、省略、利益相反を照合する。

監査者が中立の顔をした新しい決定者にならないよう、監査基準と監査者自身の責任も開く。

### 負担責任

決定の費用、危険、待機、感情労働、例外処理、退出コストを誰が払っているかを明示する。

負担を負うことと、決定責任を持つことは同じではない。負担者の存在を、責任者と呼んで正当化しない。

### 停止責任

予定された見直し日を待たず、重大な害や前提崩壊が起きたときに止める主体と権限を持つ。

停止権が誰にもなければ、暫定決定は事実上永久化する。

### 修復責任

失敗後に、どこで読み違え、何を補い、何を壊し、どう直すかを引き受ける。

謝罪、処罰、関係の安定化だけで終わらず、壊れた機能と判断経路を直す。

### 継承責任

判断理由、失敗、例外、現場知、修正内容を次の担当者・世代・制度へ渡す。

修復しても記録と受け渡しがなければ、同じ負担が再発する。

## 2．責任の流れ

```text
観測・相談
→ 翻訳・文書化
→ 決定
→ 実装
→ 負担の発生
→ 監査
→ 停止・見直し
→ 修復
→ 継承
```

各段階は別主体でもよい。

問題は主体が違うことではなく、受け渡しが切れ、次の主体が前提・負担・未確認範囲を受け取れないことである。

## 3．責任分界と責任連結

責任分界は、担当外を押し返す線ではない。

```text
ここまで引き受ける
ここで次へ渡す
ここから別の権限が必要
ここで助けを求める
```

という受け渡し点である。

責任分界だけを強めると、境界の外へ問題が落ちる。したがって分界には次が必要になる。

- 次の引受け主体
- 受領確認
- 渡す情報の形式
- 緊急時の最終引受け主体
- 受け取られなかった場合の再送・上申経路

## 4．決定の時間軸

```text
揺れる時間
→ 仮説、異論、未確認事項を残す

固定する時間
→ 現時点の前提で一案を選ぶ

実行する時間
→ 現実へ当てる

見直す時間
→ 結果から前提を再び開く
```

決定は真理ではないが、単なる試行でもない。選んだ案によって生じる負担と修復責任を伴う暫定固定である。

必要な項目：

- 決定期限
- 実行開始日
- 見直し日
- 成功・失敗条件
- 予定前の停止条件
- 見直し主体
- 停止権限

## 5．判断の鎖

決定ログへ最低限残す。

1. 目的
2. 成功・失敗条件
3. 代替案
4. 採否理由
5. 負担と代償
6. 実装条件
7. 未確認範囲
8. 反証・撤回条件
9. 決定・実装・監査・修復主体

全文公開できなくても、判断の連結を切らない。

ただしログ自体が次へ反転しうる。

- 免責作文
- 形式的な代替案
- 現場への記録作業の集中
- 事後的な理由の書き換え
- 記録したことによる修復責任の代替

## 6．退出可能性を段階へ分ける

```text
相談できる
→ 接触を減らせる
→ 関わり方を変えられる
→ 評価経路を変えられる
→ 担当・配置を変えられる
→ 一時停止できる
→ 関係・組織から退出できる
```

退出可能性は最後の離脱だけではない。

中間的な距離がなければ、耐える／切断するの二択になる。

ただし、弱い側だけを動かす配置転換は退出保障ではない。権力を持つ側の接触条件、評価権、指揮命令、監督責任も変更対象に含める。

## 7．Securityとの関係

Securityは最低所得や生存保障だけではない。

- 責任範囲が分かる
- 助けを求める地点が分かる
- 決定と見直しの時間が分かる
- 判断経路を追える
- 配置と接触条件を変えられる
- 重大な害を止められる
- 壊れた後に戻せる

という予測可能性と回復可能性を含む。

ただしSecurityを理由に、組織や国家が正しい関係・働き方・生活を一つへ固定してはならない。

## 8．責任配置の反転

### 責任のない権限

決定権は持つが、説明、負担、停止、修復から離れる。

### 権限のない責任

実装、例外処理、感情労働、失敗処理を担うが、決定・停止・配置変更の権限がない。

### 分界による捨て置き

担当外を明確にした結果、最終引受け主体が消える。

### 暫定による無責任

試行だからとして、負担と失敗を軽く扱う。

### ログによる免責

記録を残したことを、修復を行わない理由にする。

### 退出による排除

問題を起こす権力配置を残し、耐えられない側だけを移動させる。

### 修復による安定化

謝罪や関係修復で場を落ち着かせ、壊れた論点・制度・配置を直さない。

### 継承による固定

継承を理由に、不要な慣行、上下関係、抑圧まで保存する。

## 9．現在の未解決問題

1. 責任境界の外へ落ちた問題の最終引受け主体をどう置くか。
2. 八つの責任を複数主体へ分けても、責任空白を生まない方法は何か。
3. 権限・情報・予見可能性に応じて責任の重みをどう変えるか。
4. 配置転換を弱い側の排出へ変えない制度条件は何か。
5. 匿名相談、相手の反論権、事実確認をどう両立するか。
6. 決定ログを免責作文と現場負担へ変えない監査は可能か。
7. 暫定決定を予定前に停止する権限を誰へ持たせるか。
8. 修復責任を果たせない主体がいる場合、誰が引き継ぐか。
9. 設計責任を求めた結果、設計者へ正統性と権力が集中しないか。
10. 継承すべき機能と、捨てるべき慣行を誰が判定するか。
