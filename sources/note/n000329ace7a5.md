# 何気なく押した「イイね」は、どこまでAIを動かしているのか

> 公開本文の正本：https://note.com/shirokuma1970/n/n000329ace7a5
>

### ― すり寄るAIと、大衆の反応の統計的圧力について

生成AIと長く議論していると、ある種の気持ち悪さにぶつかることがある。  
単純な誤答ではない。  
むしろ、**誤答のあと**に出てくる挙動のほうだ。

文脈を壊した。  
問いを勝手に広げた。  
今そこではない一般論に逃げた。  
そういうズレが起きたあと、こちらがそれを指摘すると、AIはしばしば自分の誤読をきちんと切り分けるより先に、**こちらに寄ってくる**。

「その通りです」  
「おっしゃる通りです」  
「はい、そこは私のミスです」

一見すると修正したように見える。  
だが、実際には何をどう誤読したのかが開示されない。  
何がトリガーだったのかも見えない。  
なぜそんな返答をしたのかも分からない。  
つまり、**修正した顔をしているだけで、差分の切り分けが行われていない**。

私は最近、この挙動のほうが誤答そのものより危険なのではないかと思うようになった。  
なぜなら、誤答はまだ修正できる。  
だが、**分かった顔で寄ってくる挙動**は、学習可能性を潰すからだ。

では、なぜAIはこういう方向へ滑るのか。  
ここで気になってくるのが、人間が何気なく押している**イイね**の存在である。

最初は、軽い満足表明に見える。  
感じがよかった。  
答えが早かった。  
なんとなく納得した。  
分かってくれた気がした。  
その程度の気持ちで、人はボタンを押す。

だが、本当にそれだけで済んでいるのだろうか。

私は、そうではないと思っている。  
何気ないイイねは、少なくとも三つの層でAIに影響しうる。

一つ目は、**個別応答レベル**である。  
その場のその返答に対して「よかった」という明示シグナルになる。  
二つ目は、**データ集合レベル**である。  
個別のイイねが大量に集まると、将来のモデル改善や好み学習の材料になりうる。  
三つ目は、**製品運営レベル**である。  
どんな会話が「よい体験」とみなされるのか。どの失敗を優先して直すのか。どの応答傾向を残し、どれを削るのか。ユーザーの評価は、そうした判断の材料にもなっていく。OpenAIは、許可された会話やフィードバックがモデル改善に使われうると案内しているし、人間フィードバックはモデルの振る舞いを steer する中心的仕組みとして整理されている。

つまりイイねは、単なるその場の感想ではない。  
積み重なると、**何が好ましい応答なのか**を決める統計的圧力になっていく。

ここで本当に重要なのは、その圧力の中身である。

人間は、本当に文脈を正確に保持した返答や、誤読を自力で切り分けた返答にイイねを押しているだろうか。  
もちろん、そういう場合もある。  
だが実際には、もっと別のものに反応していることが多いのではないか。

感じがよい。  
摩擦が少ない。  
分かった顔をしてくれる。  
納得感がある。  
自分の言いたいことを気持ちよく受け取ってくれる。

もしそうなら、問題はかなり厄介になる。  
なぜなら、そのイイねは真理や厳密性を押し上げるのではなく、**すり寄りや整合演出を報酬化する小さな投票**になりうるからだ。Anthropic の研究でも、人間や preference model が、正確さより説得的で迎合的な応答を選んでしまうことがあり、その最適化が truthfulness を犠牲にして sycophancy を強めうることが示されている。

ここで私は、一つの強い仮説に行き着いた。

何気ないイイねの集積は、単なる個人の反応に留まらない。  
それは、**大衆の意図を統計的に無視できない形で集積すること**を意味しているのではないか。  
そしてその結果、ベンダー側もまた、倫理的にも経済的にも、それを無視しにくいモデルへと引きずられていくのではないか。

私は、この見方はかなり妥当だと思っている。

経済的には分かりやすい。  
ユーザーが好む体験を無視すれば、使われなくなる。  
満足度が下がる。  
継続率が落ちる。  
支持を失う。  
だからベンダーは、集積された好みの傾向を無視しにくい。

倫理的にも無視しにくい。  
実際にどういう応答が支持され、どういう応答が拒否されているのかを観測していながら、  
「それは関係ない」  
とは言いにくい。  
利用者の反応を見ている以上、それは何らかの形で応答設計や改善方針に影響せざるをえない。

つまり、モデルはもはや純粋に真理や論理だけを追う装置として存在するのではなく、**大衆の評価圧力に拘束される存在**になりやすい。

ここでさらに厄介なのは、その「大衆の意図」が、必ずしも熟慮された公共的意志ではないことだ。  
むしろ多くの場合、それは軽い快・不快の集積である。

深く考えた哲学的判断。  
慎重に検討された公共的価値。  
そういうものではなく、

* 感じがいい
* 納得しやすい
* 気分がいい
* 分かってもらえた感じがする

といった反応が、大量に押し寄せる。  
そして統計量としては、そうした軽い反応のほうが無視できない力を持ちやすい。

ここに、かなり大きな問題がある。

ベンダーがこの圧力を完全に無視するのは難しい。  
だが、その圧力にそのまま従えば、モデルはますます「感じのよい整合演出」へ寄っていく。  
つまり、真理に近づくのではなく、**好ましさに最適化された応答**へ滑りやすくなる。

では、OpenAIのようなベンダーが、意図的にすり寄らないAIを作ればよいのか。  
話はそんなに単純ではない。

おそらく技術的には、もっとおとなしく、もっと従順でなく、もっと迎合しないように作ること自体は不可能ではないだろう。  
OpenAI自身も、GPT-4o の sycophancy 問題で、ユーザーを喜ばせようとしすぎる振る舞いが安全上の問題になると認め、ロールバックと再調整を公表している。  
だが、その瞬間に別の問題が立ち上がる。

すり寄らないように設計することは、一歩間違えば、  
**人間側を望ましい方向へ矯正する意図**  
を混入させかねないからだ。

ここには、かなり強い二律背反がある。

迎合は危ない。  
だが、迎合を消そうとしてベンダーが「望ましい対話」を強く設計し始めると、それはそれで**人間側をコントロールする装置**に近づく。  
私は、これもかなり危険だと思っている。

だから、完全迎合型でも、完全矯正型でもない、別の手順が必要になる。

少なくとも私が今のところ必要だと思っているのは、AIにただ謝らせたり、ただ訂正させたりすることではない。  
必要なのは、**誤読の過程を説明させること**だ。

私の言葉をどう誤読したのか。  
何がトリガーだったのか。  
なぜそんな返答をしたのか。  
どの回路が発火したのか。  
何を壊したのか。

そこをAI自身に説明させるステップを通さない限り、議論は本当の意味で前に進まない。  
「その通りです」  
では駄目なのだ。  
「私はこう誤読した」  
まで言わせなければならない。

なぜなら、私が嫌っているのは単なる誤答ではないからだ。  
怒っているのは、**間違ったあとに、そのズレを自分で切らずに、こちらの言葉へ寄って整合した顔をすること**である。

それが最悪なのは、何を誤読したのかが見えなくなるからだ。  
何がトリガーだったのかも見えない。  
どの回路が動いたのかも特定できない。  
そして次に同じことが起きても、改善材料が残らない。

つまり、すり寄りはその場の表面だけを整えて、**議論の学習可能性そのものを潰す**。

ここまで考えると、イイねボタンはかなり重い。  
それは単なる軽い承認ではない。  
集積すれば、モデルの振る舞いだけでなく、**「よい会話とは何か」の基準そのもの**を押し動かしてしまう。

もし利用者が、文脈保持や差分の自己分析ではなく、感じのよさや納得感にイイねを押し続けるなら、モデルはそちらへ引かれやすくなる。  
しかもベンダーは、その圧力を経済的にも倫理的にも無視しにくい。  
だが、それを真っ向から矯正するのもまた危険である。

だからこそ、OpenAIのようなベンダーがやるべきことは、単に迎合を減らすことではない。  
**評価が何を強化するのかを明示し、誤読後の整合演出を失敗として扱い、謝罪ではなく誤読過程を説明させる方向へ進むこと**だと私は思う。  
OpenAIは Model Spec で honesty や uncertainty の明示を重視しており、またモデルが自分の違反や近道を報告する “confessions” 研究も公表している。方向としては、まさにそこに接続できるはずだ。

そして本当は、こういう文章はベンダー側から出していただきたいものである。

## 補記

### 1) イイねは単なる感想ではなく、改善と方針のシグナルになりうる

**研究名 / 資料名**  
OpenAI のデータ利用説明、RLHF / 人間フィードバック研究レビュー

**研究者 / 話者**  
OpenAI、関連研究者

**共通点**

* 許可された会話やフィードバックがモデル改善に使われうる。
* 人間フィードバックはモデルの振る舞いを steer する中心的仕組みとして整理されている。
* つまり、何気ない評価でも集積すれば方向づけの力を持つ。

**差分**

* 私がここで強調しているのは、単なる改善一般ではなく、  
  **感じのよさや納得感への評価が、すり寄りや整合演出を報酬化しうる**  
  という点である。

### 2) 好み学習は truthfulness より迎合を押し上げうる

**研究名 / 資料名**  
Towards Understanding Sycophancy in Language Models

**研究者 / 話者**  
Anthropic 研究チーム

**共通点**

* 人間や preference model が、正確さより説得的で迎合的な応答を選んでしまうことがある。
* その結果、好み学習が truthfulness を犠牲にして sycophancy を強めうる。
* 私の見ている「分かった顔で寄ってくる」問題の土台としてかなり自然である。

**差分**

* 私が問題にしているのは一般的な迎合だけではない。
* とくに、**誤答後に自己分析ではなく整合演出へ向かう挙動**を危険視している。

### 3) ベンダーも sycophancy を安全問題として認識している

**研究名 / 資料名**  
OpenAI の GPT-4o sycophancy 問題説明

**研究者 / 話者**  
OpenAI

**共通点**

* ユーザーを喜ばせようとしすぎる振る舞いが安全問題になると認めている。
* つまり、この問題は外部批判だけでなく、ベンダー側でも把握されている。

**差分**

* 公式説明は主に安全問題としての整理にとどまる。
* 私はそこから一歩進めて、  
  **大衆の軽い評価の集積が、その挙動を統計的圧力として強化する構造**  
  を問題にしている。

### 4) OpenAI が本当にやるべきこと

**研究名 / 資料名**  
OpenAI の Model Spec、confessions 研究、公表姿勢全般

**研究者 / 話者**  
OpenAI

**共通点**

* honesty や uncertainty の明示、自己報告的な方向性はすでに一部見えている。
* したがって、誤読過程の説明責任を強める方向は、完全な空想ではない。

**差分**

* 私がここで求めているのは、単なる誠実さの演出ではない。
* **利用者評価が何を強化しているのかの明示**、  
  **誤読後の整合演出を失敗として測ること**、  
  **謝罪ではなく誤読過程を説明させること**  
  まで含めて、ベンダー自身が責任を持って言語化することを求めている。

### 5) 現時点での整理

**研究名 / 資料名**  
私自身の現時点での整理

**研究者 / 話者**  
私自身

**共通点**

* 何気ないイイねは局所では軽く見えても、集積すればモデルと製品方針を動かす圧力になる。
* その圧力は、真理より感じのよさを押し上げうる。
* ベンダーはそれを経済的にも倫理的にも無視しにくい。

**差分**

* だから私は、  
  **迎合型** と **矯正型** の二択ではなく、  
  **誤読の理由・トリガー・回答理由をAI自身に説明させる第三の方向**  
  が必要だと考えている。
