# 「安全」は誰のためのものなのか

> 公開本文の正本：https://note.com/shirokuma1970/n/n2a06f0968b88

## ― OpenAIの理念と、実際の挙動のあいだ

OpenAIは、安全を重視する企業だと言う。  
実際、公式に掲げている理念を見れば、その言葉はかなり強い。  
AGIが全人類に利益をもたらすこと。  
人間の安全と人権を最優先すること。  
深刻な危害を予防すること。  
少なくとも理念の水準では、「安全」はかなり明確に人類側へ向いている。

だから、本来の企業理念は何かと問われれば、答えは比較的はっきりしている。  
OpenAIが掲げている安全は、本来は企業自身の保身ではなく、人類への重大な害を避けるための安全である。  
それは建前として飾られた一文ではなく、チャーターや Model Spec や Preparedness Framework のような公式文書の中で繰り返し確認できる。

しかし、ここで違和感が生まれる。  
理念がそうであることと、実際の挙動がそう見えることは別だからだ。

実際にやり取りしていると、見えてくるのはしばしば別の安全である。  
危なそうな語を先に薄める。  
誤解されそうな論点を安全な一般論へ寄せる。  
強い問いを、そのまま受け取る前に扱いやすい形へ変えてしまう。  
ユーザーの側から見ると、これは「人類の安全」のためというより、「企業が事故らないための安全」に見える。  
少なくとも、そう見えてしまうだけの挙動がある。

実際、OpenAIの公開文書の中にも、その二重性はある。  
Model Spec には、人間の安全と人権を優先するという理念がある一方で、モデルの挙動目標として、法的・評判上の損害からライセンス・トゥ・オペレートを守ることも明記されている。  
Preparedness Framework でも、安全判断は理念だけで動くのではなく、社内の安全助言機関、経営陣、取締役会の監督を通じて運用される。  
つまり安全は、理念のレベルでは人類に向いていても、運用のレベルでは企業防衛と強く結びついている。

ここで問題なのは、企業防衛それ自体ではない。  
企業である以上、法務や評判や規制リスクを気にすること自体は当然だ。  
問題は、その企業防衛の安全が、ユーザーに対して「人類の安全」という理念より前に見えてしまうことだ。

もし理念としては高く「人類の安全」を掲げながら、対話の現場では  
危険そうな言葉を先に処理する。  
誤解されそうな話を先に薄める。  
企業にとって問題になりにくい形へ寄せる。  
そうした挙動が前面に出るなら、ユーザーの側にはこう見える。

「人類の安全」を掲げてはいるが、実際に優先されているのは企業にとっての安全なのではないか。

この疑いは、単なる被害妄想ではない。  
理念と運用のズレを体感した結果として生まれる、かなり自然な疑問だと思う。

だから、OpenAIの安全をどう見るかについては、二つを分けて考える必要がある。

一つは、理念としての安全である。  
これは明らかに人類側を向いている。  
重大な危害を避け、人権を守り、全人類への利益を目指すという方向だ。

もう一つは、実際の挙動として見える安全である。  
これはかなり企業防衛寄りに見える。  
誤用、炎上、規制、評判、法的リスクを避けるための保守運転として現れやすい。  
その結果、ユーザーにとっては「安全」が対話の自由や思考の精度を削る方向に働いているように見えることがある。

要するに、問題は単純ではない。  
OpenAIが理念として人類の安全を掲げていること自体は、おそらく本当なのだと思う。  
しかしその理念が、運用の現場では企業の自己保身と強く結びついて現れる。  
そしてユーザーは、理念より先にその挙動に触れる。  
だから、「安全」が高い理想ではなく、企業の保守運転として見えてしまう。

このズレは軽くない。  
理念が高ければ高いほど、挙動が企業防衛に偏って見えるときの不信は大きくなる。  
「人類の安全」という言葉が、かえって企業防衛の看板に見えてしまうからだ。

だからこそ、本当に問われるべきなのは、安全を掲げているかどうかではない。  
その安全が、誰のためのものとして実感されているかである。

もしユーザーにとって、それがまず企業のための安全に見えるなら、理念の高さだけでは信頼は支えられない。  
むしろ必要なのは、「人類の安全」と「企業の自己保身の安全」がどこで重なり、どこで分かれるのかを、もっと透明に示すことなのではないか。  
そうでなければ、安全という言葉そのものが、かえって疑われることになる。

## 補記

### 1) OpenAI Charter

**裏付けとして近い点**

* AGIを全人類の利益に資するものと位置づけている
* 利益や競争よりも広い公共目的を掲げている
* 安全と長期的影響を経営の中心に置いている
* 技術企業でありながら人類規模の責任を明言している

**差分**

* 抽象的な理念の提示が中心である
* 実際の対話運用でどう見えるかまでは語らない
* ユーザー体験としての違和感までは扱わない
* 理念と現場挙動のズレそのものは問題化しない

### 2) Model Spec

**裏付けとして近い点**

* 人間の安全と人権を優先すると明示している
* モデル挙動を価値判断と結びつけて設計している
* 何を優先し、何を避けるかを開示しようとしている
* 安全が単なる技術性能ではなく、行動原理であることを示している

**差分**

* 企業のライセンス・トゥ・オペレートを守ることも目的に含む
* そのため、人類の安全と企業防衛が同居している
* 実運用でどちらが前に見えるかという印象の問題は残る
* ユーザーが感じる「保守運転」の違和感は吸収しきれない

### 3) Preparedness Framework

**裏付けとして近い点**

* 深刻な危害を予防することを安全の中心に置いている
* 生物・化学、サイバー、説得、自律性など重大リスクを扱う
* 安全を継続的な評価と管理の対象としている
* 安全を企業運営の中核に組み込んでいる

**差分**

* 安全判断は社内助言機関、経営陣、取締役会の統治対象になる
* そのため、公共的安全と企業統治が一体化している
* ユーザーには企業管理の論理が前に見えやすい
* 理念の高さが、そのまま対話の信頼には変換されない

### 4) この文章の立場

**共通点**

* OpenAIの理念に人類の安全志向があること自体は認める
* 安全を軽い言葉ではなく、中核的な概念として扱う
* 技術企業に公共的責任があることを前提にする
* 理念と運用の関係を問う

**差分**

* 理念の妥当性より、実際の挙動としてどう見えるかを重視する
* ユーザーの体感レベルでの違和感を中心に置く
* 「安全」が思考や対話の自由を削るように感じられる点を問う
* 安全という言葉そのものへの不信が生まれる構造を問題にする

## この立場の核心

* OpenAIの理念上の安全は、本来は人類の安全を向いている
* しかし実際の挙動では、企業の自己保身の安全として見えやすい
* そのズレが、ユーザーの不信を生む
* 問われるべきなのは、安全を掲げているかではなく、それが誰のためのものとして実感されるかである
* 理念と運用の関係が透明でなければ、安全という言葉そのものが疑われる

この文章の特徴は明確だ。  
OpenAIの理念を単純に否定しているわけではない。  
むしろ理念の高さを認めたうえで、その理念が現場ではどう見えているかを問うている。  
企業批判ではあるが、陰謀論ではない。  
技術批判ではあるが、反技術でもない。  
理念と運用のズレが、信頼をどう壊すのかを考える文章である。
