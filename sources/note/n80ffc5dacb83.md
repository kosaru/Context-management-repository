# OpenAI・Anthropic・Googleは現在どこへ向かっているのか

> 公開本文の正本：https://note.com/shirokuma1970/n/n80ffc5dacb83
>
> このファイルは文脈解析用の取得時スナップショットです。

## ― 「プロンプトの工夫」から「エージェントの設計」へ

生成AIについて話すとき、いまだに「プロンプトエンジニアリング」という言葉が、うまい一文を見つける技術のように理解されることがある。  
だが、少なくとも主要ベンダーの現在の方向性は、もうそこにはない。  
OpenAI、Anthropic、Googleはいずれも、単発の文言調整より、**システム全体としてどうAIを安定して動かすか**へ重心を移している。これは、各社の公式資料を見ればかなりはっきりしている。

つまり、いま起きているのは「プロンプトエンジニアリングの高度化」というより、**プロンプトという入口を含んだ設計全体の再編**である。  
各社とも、プロンプト単体より、評価、ツール利用、状態管理、文脈管理、エージェント運用へと進んでいる。  
ただし、同じ方向へ進んでいるように見えて、各社の重心はかなり違う。  
私はそこを切り分けて見たほうがよいと思っている。

## OpenAIは「実運用に耐えるエージェント基盤」へ向かっている

OpenAIの現在の方向性はかなり明確だ。  
Responses API への移行を「path forward」とし、推論の状態保持、ツール呼び出し、評価を回しながらの改善、reasoning effort や verbosity の制御まで含めて、GPT-5 を**本番運用に耐えるエージェントとして扱う**方向を前面に出している。  
しかも、単に「賢いモデルがあります」ではなく、  
まず移行しろ。  
eval を回せ。  
推論を観察しろ。  
テンプレート化しろ。  
という形で、かなり実務的な運用手順として提示している。

この方向を一言で言えば、OpenAIは  
**高い steerability を持つ推論モデルを、評価と状態管理を前提に運用する実務基盤**  
へ向かっている。  
私はそう見ている。  
つまり、OpenAIの中心課題は、モデルの能力そのもの以上に、**それをどう production で安定稼働させるか**にある。  
ここでは、プロンプトは単体の技法ではなく、運用設計の一部になっている。

## Anthropicは「文脈をどう設計するか」を中心に置いている

Anthropicは、かなりはっきりと「context engineering」という言葉を前に出している。  
しかもそれを、prompt engineering の否定ではなく、**自然な発展形**だと書いている。  
ここで言う context engineering とは、プロンプト文だけではなく、推論時にモデルへ渡るトークン全体、つまり文脈全体をどう最適化するか、という話である。  
言い換えると、Anthropicは  
**モデルに何を言うか**  
より、  
**モデルに何が見えている状態を作るか**  
を中心課題としている。

これはかなり大きい違いだ。  
OpenAIが本番運用や評価反復の色を強く出しているのに対して、Anthropicは、**エージェントの steerability を決めるのは文脈の設計である**という認識を、かなり前面に出している。  
だからAnthropicの方向性は、  
**文脈管理を中心に、エージェントを制御可能にする方向**  
だと言える。  
ここでは、プロンプトは一文の工夫ではなく、文脈全体を編成する作業へ吸収されている。

## Googleは「ツールと世界に接続されたマルチモーダル・エージェント」へ向かっている

Googleの方向はまた少し違う。  
Gemini の公式資料では、もちろん prompt design 自体も扱っている。  
だが、そこで強調されているのは、反復的に改善すること、明確で直接的な指示、構造化された出力だけではない。  
Interactions API では、function calling、built-in tools、structured outputs、MCP を備えた**agentic capabilities**が前面に出ている。  
さらに Gemini Deep Research Agent は、検索し、読み、計画し、統合する自律ループを回すエージェントとして提示されているし、computer use はデジタル環境を直接操作する方向まで視野に入っている。

この流れをまとめると、Googleは  
**検索・ツール・環境操作に強く接続されたマルチモーダルなエージェント基盤**  
へ向かっている。  
つまり、単に言語モデルをどう使うかではなく、Googleがもともと持っている検索・地図・情報環境との接続を活かして、**世界に触れるエージェント**を作ろうとしているように見える。  
ここでは、プロンプト設計は単独では存在せず、ツールと行動の設計の中に入っている。

## 三社は同じ場所にいるのではない

ここまでを見ると、三社はみな「プロンプトの時代は終わった」と言っているようにも見える。  
だが、私はそう単純ではないと思っている。  
正確には、三社とも**プロンプトを孤立した技法としては扱わなくなった**のであって、その先で何を中心課題にするかは違う。

OpenAIは、**評価・状態・制御を含めた本番運用**に重心を置いている。   
Anthropicは、**文脈の設計そのものをエージェント制御の中心**に置いている。   
Googleは、**ツール・検索・環境操作まで含むマルチモーダルな行為能力**へ向かっている。

だから、同じ「エージェント志向」と言っても、OpenAIは運用、Anthropicは文脈、Googleは接続と行為、という違いがある。  
私はこの違いを、かなり重要だと思っている。  
なぜなら、ユーザーが今なお「プロンプトをうまく書けばAIを使いこなせる」と思っているなら、すでに主要ベンダーの実際の進み方とはずれているからだ。

## では、ユーザー側はどう受け止めるべきか

ここで大事なのは、ベンダー側の方向性を知ったうえで、なお**ユーザー側には別の課題が残る**ことだ。  
ベンダーは、システムを安定させ、評価し、制御し、ツールとつなぎ、本番で動かそうとしている。  
それはベンダーとして正しい。  
だが、それだけでは、ユーザーの思考主権は守られない。

なぜなら、どれだけベンダーが高度な context engineering や agent design をしても、ユーザーが  
「気持ちよく返ってきたから正しい」  
「整理されたから考え抜いた」  
と受け取ってしまえば、主権は簡単に滑っていくからだ。  
つまり、ベンダー側の設計論が進めば進むほど、ユーザー側には逆に、**AIが何をどう読んだかを観測する稽古法**が必要になる。  
私は、ここを見落とすと、現在の方向性をただの「便利化」としてしか理解できなくなると思っている。

だから、OpenAI・Anthropic・Googleが現在どこへ向かっているのかを一言で言えば、  
**三社とも、プロンプト単体の工夫から、エージェントを実際に運用するための全体設計へ向かっている。**  
ただし、  
OpenAIは本番運用、  
Anthropicは文脈設計、  
Googleは世界との接続、  
にそれぞれ重心がある。  
そして、ユーザー側がそれをどう受け止めるかは、また別の問題である。

私は、この「別の問題」を今後もっと書く必要があると思っている。  
ベンダー側は、確かに前に進んでいる。  
だが、その前進だけでは、人間が生成AIとどう付き合うべきかの答えにはならない。  
そこには別の稽古法が要る。  
いまは、その切り分けをまずは見失わないことが大事なのだと思う。
